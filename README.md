# Nockra Final Click-Fix Pack

This build removes the interaction gate that could leave the page visually loaded but non-responsive.

## What changed

- `app.js` is loaded directly by the page. It is no longer injected through a timed bootstrap loader.
- UI event handlers are attached before wallet restoration, RPC reads, or Pons reads can delay the page.
- Browser-storage access is guarded. If local storage is blocked by privacy settings, an embedded browser, or a restricted preview, the website remains clickable.
- Wallet connection no longer waits for ethers/CDN loading. Account authorization and Robinhood Chain switching happen first. Contract-signing support is attached separately.
- Tool cards use same-page hash routing instead of forcing a page reload.
- Theme, Chinese/English switching, Tools menu, mobile navigation, wallet menu, Connect and Disconnect remain usable independently of RPC/CDN status.
- Direct `.html` access and extensionless public routes are both recognized.
- Vercel and Netlify route rules point to concrete static public pages.

## Deployment

Deploy the **contents of this folder** as the site root. The archive already places `index.html`, `app.js`, `i18n.js`, `token-artifact.js`, `styles.css`, `config.json`, `vercel.json`, `_redirects`, `assets/`, and `api/` at the root.

Do not upload an extra parent directory above these files.

## Public project configuration

Public brand/project values live in `config.json`. This remains the public source of truth for the coin name, ticker, network label, contract address, X URL and Pons Family buy URL template.

The Buy destination is generated by replacing `{ca}` in:

`https://ponsfamily.com/launchpad/{ca}`

with the configured contract address.

Never place private keys, seed phrases, wallet credentials or API secrets in `config.json`.

## Public routes

- `/`
- `/{ticker in lowercase}`, currently `/nockra`
- `/docs`
- `/privacy`
- `/terms`
- `/disclaimer`
- `/cookies`
- branded 404
- tool workspaces at `/#tool/<tool-id>`

Physical fallback pages are included as well as hosting rewrites.

## Wallet behavior

When disconnected, **Connect Wallet** calls the injected EVM wallet directly. Once connected, clicking the same wallet control opens:

- Copy address
- View on explorer
- Disconnect

The interface can request Robinhood Chain switching or add the chain when the wallet supports those methods.

## Pons V2 token image upload

The Pons V2 launch form uses an image file chooser for PNG, JPEG or WebP. The browser creates a preview and optimizes large raster images before upload. The uploaded IPFS URI is passed internally to the Pons V2 launch call.

The included Vercel endpoint is `api/upload.js`. For live image uploads, set a server-side environment secret named `PINATA_JWT`. Do not put that secret in `config.json`.

## Themes, language and font

- Dark and light themes
- English and Chinese UI switching
- Poppins only

Preferences use local storage when available. If storage is unavailable, the UI continues working and simply does not persist the preference between sessions.

## Verification performed

The included `tests/qa.mjs` checks routes, the tool list, Robinhood Chain configuration, dynamic Buy URL generation, wallet flow, Chinese/theme controls, Poppins, image upload wiring, public cleanliness, and interaction hardening.

A browser smoke test was also run in a storage-denied environment. Tools menu, theme toggle, language toggle, tool hash routing, wallet Connect, wallet menu and Disconnect remained responsive with no page errors.

Run static QA with:

```bash
node tests/qa.mjs
```

## Mainnet note

Blockchain writes still require a compatible injected EVM wallet, RPC access, ETH for gas, the relevant token permissions, and explicit wallet approval. No mainnet transaction is silently broadcast by the website.
